# 代码视频的能力边界（2026-11 实测记录）

> 结论先行：**代码渲视频擅长的不是"表演"，是"信息组织"。**
> 任何需要"逐帧美术判断"的东西（人物表情、喜剧节奏、镜头表演）都不该用这条路做，
> 任何靠"排版 + 图形 + 数据 + 声音"承载的内容都能做到发布水准。

这份文档是踩坑记录，不是理论。每一条都对应一次实际渲染失败。

## 一、能做（已验证到可发布）

| 类型 | 关键手段 | 参考实现 |
|---|---|---|
| 数据 / 图表解读 | 大字数字 count-up、折线生长、对比条、排名 | 深色瑞士排版（`swiss-editorial-dark` 待做） |
| 卷宗 / 事件还原 | 档案纸、证物框、红线、时间轴、印章 | `archive-dossier` ✅ |
| 白板 / 黑板讲解 | `stroke-dashoffset` 逐笔绘制、手绘抖动路径 | 未做，方法已验证（`handLine()`） |
| 排版字效 | 逐句砸字、遮罩、位移、音效对齐 | 未做，成本最低 |
| 科普图解 | 线条图、箭头、流程、地理示意 | `paper-editorial` ✅ |

共同点：**画面信息不依赖"角色此刻在想什么"**。

## 二、不能做（试过，失败）

### 2.1 人物表演 / 漫剧 / 喜剧

三种做法全部试过，都不到发布水准：

| 做法 | 具体实现 | 失败原因 |
|---|---|---|
| 参数化关节 rig | FK 骨骼 + 关键帧轨道 + 插值 | 出图稳定但**没有表演**：能站能挥手，做不出"表情一僵""嘴角抽一下" |
| 皮影剪影 + 铆钉 | 侧身剪影、喇叭袖、铆钉、镂空 | 造型成立了，但**动作是"关节转动"而不是"发力"**，看着像机械人 |
| 手绘漫画格 | 出血裁切、网点只铺暗面、拟声字出画 | **单帧好看，连起来没有节奏**：一格一格手写，成本随长度线性爆炸 |

根因（按影响排序）：

1. **笑点靠"度"**：同一张脸，眉毛高 3px 是呆，低 3px 是凶。这个"度"只能靠眼睛判断，不能靠参数猜。
2. **节奏靠剪辑直觉**：什么时候切、切多长、留几帧空白，是作者判断，不是公式。
3. **一致性靠美术功底**：换一个机位，剪影就得重画；参数化只能保"形状一致"，保不了"画得对"。
4. **我看不见运动**：只能看静帧，运动质量（缓动、预备、跟随、挤压）无法自评。

**判定规则**：如果需求里出现"演""表情""笑点""对话""漫剧""角色"，先说明这条路走不到发布水准，再给"无表演替代方案"（见第三节）。

### 2.2 需要真实素材的画面

- 新闻照片、影视截图、明星、品牌物料：**不抓、不贴、不复刻**。
- 替代写法：证物框里放抽象条纹占位并标注 `EVIDENCE 01`，或让用户提供授权素材。
- 已验证的负面案例：证物框里塞"斜纹渐变"当照片，一眼假，会把整片的专业感拉低。

### 2.3 真实数据可视化（没有来源时）

- 扩散、增长、排名类画面若无可靠数据，**只能做"示意"，且必须写明是示意**。
- 不要为了让画面好看而编造播放量、粉丝数、增长率。

## 三、替代方案：把"表演"换成"证据"

用户想要"好玩/有梗"的内容时，不要硬做人物，用这套替换：

| 用户想要 | 换成 | 为什么成立 |
|---|---|---|
| 一个人做动作 | 证物框 + 时间码 + 裁切框 | 观众关心"这动作哪来的"，不关心"谁在演" |
| 情绪高潮 | 印章砸下 + 鼓点 + 放大字号 | 声音和排版能制造同样的重音 |
| 对话 | 打字机逐字 + 红线连接 | 档案语言天然是"记录"，不是"对话" |
| 笑点 | 反差（严肃格式 × 荒诞内容） | 格式越正经，内容越荒谬，反差就越大 |

`archive-dossier` 这个风格就是按这个逻辑设计的：它把"梗"当"案子"办。

## 四、竖屏（9:16）的额外约束

1. **竖屏不是裁横屏**：构图重心、字号阶梯、信息密度全部要重排。
2. **底部 250px 是平台 UI 区**：字幕基线放在 `y ≈ 1400`（1080×1920），不要贴底。
3. **人物/主体占画面 55–75%**：低于 50% 会显得空，高于 80% 会挤掉标题。
4. **一行字幕 10–15 字**：横屏 22 字的规则在竖屏偏长。
5. **安全区写进 token**（`layout.safeArea`），不要每个场景各写一遍。

## 五、本轮实测数据（8 核 16G，无独显）

| 项 | 实测 |
|---|---|
| 20 秒 1080×1920 全片渲染 | ≈ 2 分钟（crf 19，concurrency 6） |
| 64 秒 1080×1920 全片渲染 | ≈ 4 分钟 |
| 单张静帧 | 3–6 秒 |
| edge-tts 6 幕旁白 | ≈ 30 秒 |
| 合成音效（65 秒） | ≈ 2 秒 |
| 现金成本 | 0 元 |

## 六、迭代纪律（省钱省时间）

1. **先出 1 张静帧**定风格，再出 3 张覆盖首/中/尾，最后才渲全片。
2. **一次只改一类问题**：构图 / 比例 / 颜色 混着改，无法判断哪次改动有效。
3. **改完必看渲出来的图，不看代码想象**。本轮 80% 的返工都来自"以为改对了"。
4. 静帧检查清单：贴地/贴边、出血裁切、文字压人物、字幕压内容、安全区、对比度。
