# 参考视频 → 可执行的拆解（视频蒸馏，本地版）

> 结论先行：做视频真正缺的不是"把长视频提炼成一个人格化技能"，而是
> **带时间码的画面证据 + 可量化的节奏参数**。
> 所以本仓库只吸收蒸馏链的**前端**：视频 → 时间码笔记 → brief / style token。
> 云端多模态蒸馏（仓颉.Skill + LongCat 那套）列为可选，且默认不碰——理由见第四节。

## 一、什么时候值得拆一条参考视频

| 信号 | 拆 | 产出用在哪 |
|---|---|---|
| 用户说"照这个视频的讲法做一期" | ✅ | 结构、钩子位置、切幕节奏 → storyboard |
| 素材是长访谈 / 播客 / 讲座，要引用其中观点 | ✅ | 观点 + 时间码 → `research/sources.md`（可核验） |
| 教程、软件实操，关键信息在画面不在口播 | ✅ | 屏幕文字 / 动作步骤 → 分镜画面事实列 |
| 纪录片式图解（天平、齿轮、周期图） | ✅ | 图解手法 → 风格与组件选型 |
| 用户只给了主题、没有参考片 | ❌ | 走原来的"主题研究 + 来源核验" |
| 参考对象是 60 秒以内的短视频 | ❌ | 拆解成本高于收益，直接看两三遍手记 |

## 二、四步链路（全程本地，0 元）

```bash
# 1) 拿到本地文件。有 yt-dlp 才需要这一步；用户给的文件直接跳过。
yt-dlp -f "bv*[height<=1080]+ba/b" -o "ref.%(ext)s" "<URL>"     # 只自己有权保存的内容

# 2) 转写（有平台字幕就用平台字幕，别浪费算力）
yt-dlp --write-subs --sub-langs "zh.*" --skip-download -o "ref.%(ext)s" "<URL>"
# 无字幕时本地转写：pip install whisperx
whisperx research/video-notes/<slug>/audio-16k.wav --model small --language zh \
         --output_format srt --output_dir research/video-notes/<slug>/

# 3) 抽帧 + 时间码笔记（本仓库脚本，自动找 Remotion 自带的 ffmpeg）
python ../scripts/video-digest.py ref.mp4 --project . \
       --subs research/video-notes/<slug>/audio-16k.srt --max-frames 36

# 4) 填表 → 提炼参数 → 进 brief / styles
```

产物结构：

```text
research/video-notes/<slug>/
  notes.md              # 元信息 + 关键帧表（画面事实/屏幕文字/可复用做法三列待填）+ 字幕时间码 + 节奏指标
  frames/kf_0001.png …  # 关键帧，Agent 直接看图填事实
  contact-sheet.html    # 精简版 ffmpeg 出 HTML；完整版 ffmpeg 出 JPG 拼图
  audio-16k.wav         # 给 WhisperX（不配音的片子可删）
```

`notes.md` 底部还有三项必须回填的量化指标：**信息点密度 / 切幕节奏 / 钩子位置**。
这三项填完，`styles/*.json` 的 `motion`、`captions`、场景时长才有依据，而不是拍脑袋。

## 三、ffmpeg 的两个档位（脚本已自动降级）

Remotion 自带的 `compositor-*/ffmpeg.exe` 是**精简构建**（实测只有 50 个 filter：有 `scale`，没有 `select` / `tile` / `showinfo`）。所以：

| 档位 | 关键帧 | 联系表 | 何时 |
|---|---|---|---|
| 完整 ffmpeg（`winget install ffmpeg`） | 场景变化抽帧 + `showinfo` 时间戳，更准 | JPG 拼图 | 拆对标片、教程 |
| Remotion 精简版 | 等间隔抽帧（逐点 `-ss` seek + `scale`） | HTML 联系表（浏览器打开） | 没装系统 ffmpeg 时的默认 |

不要为了"更准"就去装完整 ffmpeg——先跑精简版，看关键帧够不够判断结构。

## 四、和「仓颉.Skill 3.0 + LongCat-2.5」的关系（诚实评估）

那篇文章的链路是：`video-downloader`（下载 + 字幕/转写 + 关键帧 + 多模态理解）→ `multimodal_transcript.md` → 仓颉 Skill 蒸馏 → 一个可被 Agent 调用的 SKILL.md。

**它擅长的**：把 2–4 小时的访谈/播客压成"可追问的方法论"，用户问"某人怎么看买房"，能答且带原始段落。
**本项目要的**：一条新视频的画面结构。两者只在前端（转写 + 关键帧）重合。

| 维度 | 仓颉 3.0 路线 | 本仓库路线 |
|---|---|---|
| 目标产物 | 人格化方法论 skill（聊天用） | 时间码笔记 → 分镜与风格参数（出片用） |
| 依赖 | 多模态大模型 API + 视频上传到第三方临时公网地址 | 本地 ffmpeg，无网络、无上传 |
| 隐私 | 视频内容离开本机 | 不出本机 |
| 成本 | 文章自述约 755 万 token，价格按其官方标价 | 电费 |
| 可复现 | 依赖模型版本与额度 | `ffmpeg` 命令 + 帧图落盘 |

**因此默认不用**：商业访谈、内部培训、客户素材不应上传到临时公网 URL；且蒸馏出的聊天 skill 不能直接驱动 `useCurrentFrame()`。

**可以借的三个设计**（已吸收）：
1. **默认只产出一个产物**：不要把拆解拆成 8 个 md，一条片一个 `notes.md`。
2. **压力测试**：蒸馏完要能被刁钻问题打——对应到本项目就是"静帧审片 + completion gate 逐条追问"，不是"渲完就算完"。
3. **观点要带出处段落**：对应 `research/sources.md` 里视频来源必须带 `mm:ss`。

**真要用它时**：只用来做**选题阶段的观点收集**，把蒸馏出的观点当"线索"，再用可核验的原始来源（论文、官方数据、原视频时间码）替换掉二手转述；涉及未公开素材时先用本地链路。

## 五、合规红线（比效率重要）

- 参考片的**画面、音频、字幕不得进成片**，除非拿到授权并写进 `research/sources.md`。
- 不抓新闻照片、影视截图、明星、品牌物料（见 `code-video-limits.md` 2.2）。
- 引用观点带时间码：`12:30` 比"某访谈里说"可核验。
- 拆结构与方法是允许的；复刻创作者的标识性视觉（头像、口头禅排版、专属转场）不允许。
- 拆解笔记里的第三方截图只作**内部分析**，不进仓库公开发布。

## 六、实测（本机 8 核 16G / 无独显 / 无系统 ffmpeg）

| 动作 | 实测 |
|---|---|
| 95 秒 1080p30 参考片 → 30 帧 + 16k 音轨 + 笔记 | 约 10 秒（≈0.1× 实时） |
| 产物体积 | 约 7.5MB / 30 帧（960 宽 PNG） |
| 联系表 | 精简版 ffmpeg → HTML（无 PIL 依赖） |

代价可以忽略，所以"先拆参考片再写分镜"应当成为默认动作，而不是可选项。
